# 使用多线程
相关代码位置：ET\Assets\Scripts\Core\Singletons\FiberManager
我简单理解的多线程就是new很多个Thread各跑各的。
如果没有new Thread，只是async/await的话就是单线程协程。
    协程在await之前是同步的，遇到await时"挂起状态机"。等待结果或返回执行。
    协程在await后面的代码由同步上下文线程执行，是异步的。
        比如异步加载10个资源后一起返回，方法耗时由加载最慢的资源决定。
    协程的异步是"方法级"的，只能让异步代码看起来像同步，无法充分调用多核CPU。
在ET中每个Fiber就可以对应一个Thread，维护自身节点树的Update，是标准多线程。

# FiberManager
FiberManager是线程调度中心，我们默认就1个线程，也就是主线程。
在Init.cs的Update方法(理论上全局就只有这个一个mono脚本)：
TimeInfo.Instance.Update();
FiberManager.Instance.Update();
这意味着每一帧都先更新时间，再Update主线程的事件。
如果所有Fiber都注册到MainThreadScheduler，那么游戏就以单线程运行。

# SchedulerType
创建新Fiber时，要指定Scheduler类型，有三种。
SchedulerType.Main对应MainThreadScheduler，主线程。
SchedulerType.Thread对应ThreadScheduler，新建独立线程。
SchedulerType.ThreadPool对应ThreadPoolScheduler，共享线程池。

关于是否new Thread：
MainThreadScheduler没有new Thread操作。
ThreadScheduler在每次添加Fiber时执行一次new Thread。
ThreadPoolScheduler在初始化时，根据系统核心数new了指定数量的Thread。
如果是服务端且意图是让CPU跑满的话就用ThreadPool模式。

关于三种不同工作模式的运行逻辑差异：
三者都是循环调用Fiber的Update和LateUpdate。
新建的线程初始化后就不直接联系了，靠跨线程调度。

# 怎么跨线程调度
在创建Fiber后，Fiber初始化的逻辑就要跑在Fiber对应的线程上，直接抛消息：
fiber.ThreadSynchronizationContext.Post(() =>
{
    Action().NoContext();
});

比如用户按登录按钮时，主线程抛出Main2NetClient_Login消息与NetClient联系：
1.主线程调用ProcessInnerSender的Call方法，包含NetClient的ActorId和消息。
    注意这里ActorId的InstanceId为1，与Fiber初始化时创建Scene的数值一致。
2.主线程的ProcessInnerSender的SendInner方法向MessageQueue中添加消息。
    添加的消息指定了目标Fiber，将消息中的FiberId替换为发信人用于回复。
3.NetClient的ProcessInnerSender的Update方法处理MessageQueue中的1000条消息。
    ProcessInnerSender只取走自身FiberId相关的消息。
    所有邮箱都在Fiber下注册，根据ActorId中包含邮箱的InstanceId找到邮箱。
    向邮箱添加消息，触发MailBoxInvoker事件。
4.NetClient的MessageDispatcher根据message的类型、SceneType找合适的Handler。
5.NetClient的Main2NetClient_Login由MessageHandler<E, Request, Response>。
    这里已知Entity、FiberId、message，Entity强制转化为E，执行最终逻辑。
涉及到异步读写的资源是MessageQueue的消息容器，该容器是线程安全的。
